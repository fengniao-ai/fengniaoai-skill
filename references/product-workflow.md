# 商品采集与识图工作流

## 能力边界

| 能力 | 输入 | 输出 | 点数 | 限流与超时 |
| --- | --- | --- | ---: | --- |
| 商品采集 | 1688、淘宝/天猫或 Amazon 商品详情页 HTTPS URL | 结构化商品资料与远程图片 URL | 成功 1 点 | 每用户 10 QPS；同步超时不少于 45 秒 |
| 识图分析 | 通过临时 OSS 上传的本地 JPG、PNG 或 WEBP，最大 3 MB | 自然语言分析 | 成功 0.5 点 | 每用户 10 QPS；同步超时不少于 90 秒 |

两个接口都不在服务端保存历史。相同 `request_id` 再次提交仍会重新执行并再次扣点；网络状态不确定时不能自动无上限重试。

## 采集成功门槛与失败终止

商品 URL 工作流只能以 `product scrape` 的标准结果为数据源。必须同时满足：

1. CLI 返回 `ok=true`、`action=product.scrape`、`state=completed`。
2. `artifacts[role=product-metadata].local_path` 指向本次任务实际保存的 `product.json`；文件可解析，包含有效 `result`，平台、商品 ID 与原 URL 匹配。
3. 需要继续识图或制作套图时，至少一张本次商品主图已经成功下载并带有 `local_path`；只有远程 URL、下载告警或旧目录中的同名文件不算满足。

CLI 会把上述本地门槛汇总为 `data.workflow_ready_for_downstream`。只有值为 `true` 且 `workflow.state=ready` 时才能进入后续；API 返回成功但该值为 `false` 时，说明本次操作可能已经扣点但本地素材不完整，仍按 `workflow.state=blocked` 终止下游 action，不能重新采集或生成来掩盖下载失败。

任一条件不满足即为本次商品采集失败，必须停止当前 URL 工作流。CLI 对商品采集失败固定返回 `state=terminated`、`retryable=false` 和 `automatic_retry=false`；`user_retry_allowed` 只表示用户可以稍后确认发起新请求。商品采集是可能扣点的非幂等操作，Agent 不能自动重试，不能并行重复提交，也不能一边重试一边启动替代抓取。禁止使用 Agent 浏览器、WebFetch、搜索引擎、通用网页抓取、页面截图、OCR、缓存摘要、搜索结果片段或历史商品目录补齐数据；这些来源可能命中登录页、验证码、反爬提示或错误商品，不能据此报告商品标题或品类，也不能创建 `product.json`、`product-analysis.md` 或商品一致性锁。

失败后不得启动图片分析、卖点提炼、套图规划、点数确认、批量任务或任何付费生成。只交付标准错误说明和 request ID，并提供三个安全入口：用户确认后重新调用原链接；用户提供另一个可信商品链接；用户上传真实商品图片及商品事实，明确作为新的本地素材任务开始。不能把浏览器中看到的内容带入新任务，也不能建议“按文字描述生成”来继续原商品套图。若用户另行明确要求纯文字创意图，必须说明它是无法保证商品一致性的全新创作任务，不能称为该商品的 Listing 套图。

上述终止状态只作用于依赖失败 URL 的当前商品工作流，不是会话级禁用开关。用户另行提出通用生图、改图、扩图、高清、抠图或翻译需求时正常路由；用户上传可信商品素材后，以新的本地素材工作流开始。不得把失败 URL、浏览器页面或缓存中的推测带入这些新任务。

## 推荐业务链

```text
商品链接
  → 采集并保存 product.json、主图、SKU 图、详情图
  → 展示采集摘要和图片清单
  → 面向整个商品时分析全部去重主图
  → 完整读取 product.json 并保存逐图分析
  → 综合页面字段与图片证据生成 product-analysis.md
  → 用户确认商品事实、核心卖点和禁止事项
  → 电商套图 / 图片翻译 / 白底主图 / 场景图
```

用户要分析整个商品或迁移渠道时，默认分析全部去重主图，因为不同主图通常分别提供正面、侧面、结构、包装和配件证据。执行前告知去重后的图片数与预计点数（每张 0.5 点）；用户已明确要求分析时无需再逐张确认。用户只要求制作电商套图但没有要求识图时，先推荐全主图分析并给出预计点数，让用户选择“分析后规划”或“直接用现有素材规划”，不能静默增加付费操作。主图超过 10 张时先展示清单，让用户确认全部分析或选择范围。用户明确要求“第一张”“这张”或指定文件时只分析该图。SKU 图只在变体差异影响任务时追加，详情图只在需要核对卖点、包装信息或页面结构时追加。

多图识别前按文件内容去除完全重复项；最多保持 3 个同步请求在途，新请求速率不超过 10 次/秒。遇到 `429/30001` 时停止补入并按通用退避处理。

## URL 商品综合分析

URL 商品的 `analysis/product-analysis.md` 是页面采集与图片分析之间的唯一事实交接单。生成前必须完成以下步骤：

1. 从 `product scrape` 返回的 `artifacts[role=product-metadata].local_path` 定位 `product.json`；缺失时读取 `<product_dir>/product.json`。解析完整 JSON，遍历 `result` 下的标题、副标题、描述、价格、全部属性、图片列表、平台、商品 ID、来源 URL 和采集时间，不能只读取展示摘要或挑选部分属性。文件缺失、解析失败或缺少有效 `result` 时，先恢复商品采集结果；不能退化成只看图片的“完整商品分析”。
2. 汇总全部去重主图的逐图分析；SKU 图只在区分变体、规格或销售单位时追加，详情图只在核对尺寸、包装、卖点或页面信息时追加。每张图片使用稳定图片 ID。
3. 将页面字段与图片证据按“页面采集信息、图片可见事实、两者一致、字段异常、来源冲突、待用户确认”归类。字段名和值语义不匹配时标为异常，例如规格尺寸落在“纯度”字段，不能自行纠正后当作事实。
4. 生成唯一的 `<product_dir>/analysis/product-analysis.md`。重新分析时更新这份综合文档；逐图分析文件继续独立保留。

固定结构如下；没有内容的章节保留并写“无”或“未发现”，不能省略冲突与待确认章节：

```markdown
# 商品原始信息分析

## 来源页面摘要
- 平台、商品 ID、来源 URL、采集时间
- 标题、副标题、描述、价格（仅作页面采集信息）

## 页面采集属性
| 字段 | 原始值 | 状态 | 来源 |
| --- | --- | --- | --- |
| ... | ... | 正常/异常/待确认 | product.json: result... |

## 图片清单与逐图证据
| 图片 ID | 分组 | 可见事实 | 分析文件 |
| --- | --- | --- | --- |

## 页面与图片一致的事实
## 页面字段异常
## 页面与图片冲突
## SKU、销售单位、尺寸、重量、材质与品牌待确认项
## 禁止直接用于 Prompt 的信息
## 用户确认后可用于规划的商品事实
```

每条关键结论都标注 `product.json` 字段路径或图片 ID。价格、销量等时效信息，含义不清或互相冲突的字段，以及未确认的功效、性能、认证、折扣、赠品、品牌承诺，不得进入“可用于规划的商品事实”。原始 JSON 不直接塞入生图 Prompt；后续只使用用户确认后的事实建立商品一致性锁。

## 事实优先级

1. 用户明确确认的信息。
2. 商品页面采集的标题、属性、价格和描述。
3. 图片中清晰可见的主体、结构、材质、包装和文字。
4. 模型对视觉表现的概括。

采集信息与图片可见内容冲突时不要自动合并。价格可能随时间变化，不能写死到生成图片；功效、性能、认证、库存、销量、折扣和赠品不在接口承诺字段内，除非用户另行确认，否则不得生成。

## 本地目录与文件名

商品采集自动创建不覆盖旧结果的目录：

```text
<output_dir>/<platform>-<product_id>/
├── product.json
├── images/
│   ├── main/<product_id>-main-001.jpg
│   ├── sku/<product_id>-sku-001.jpg
│   └── detail/<product_id>-detail-001.jpg
└── analysis/
    ├── <image-id>-analysis.md
    └── product-analysis.md
```

再次采集同一商品时目录自动增加 `-2`、`-3` 等序号。Agent 继续识图时把 `output_dir` 设为本次返回的 `product_dir`，并把不含扩展名的图片 ID 传为 `analysis_id`，使分析文件进入对应商品目录。

同一商品的套图任务使用浅层业务目录：

```text
<product_dir>/<channel>-listing-<YYYYMMDD>/
├── plan.md
├── review.md
├── <id>.<实际格式>
├── <id>-v2.<实际格式>
└── .fengniao/
    ├── manifest.json
    ├── control.json
    └── progress.json
```

`batch_dir` 是用户可直接打开的业务目录，结果不再套 `batches/<batch_id>/results/`；隐藏目录只用于暂停、恢复和重试。任务 `id` 必须在批次内唯一、稳定且能表达用途，例如 `amazon-main-01`、`ozon-feature-02`。不要把所有任务都命名为 `image` 或复用同一个 ID；第一次重做保存为 `-v2`，绝不覆盖旧结果。CLI 仍兼容读取旧版 `<batch_dir>/results/<id>-image.<实际格式>` 批次。

## 错误处理

- `2070`：检查识图素材与参数。
- `2071`：图片分析失败；检查图片内容，确认上一请求未成功后再重试。
- `2080`：检查平台、URL 格式和平台是否匹配。
- `2081`：商品采集失败；向用户说明失败并等待其确认后，才可重试原链接。
- 商品采集失败或缺少有效本地产物：终止当前 URL 工作流，不使用浏览器或搜索降级，不执行任何后续 action。
- `2063/2064`：重新上传本地图片后再识图。
- `429/30001`：保留相同请求参数，限速后重试，不创建无限循环。
