# 电商套图视觉与 Prompt

用于把商品事实、套图用途和渠道要求编译成可直接传给 `/api/v1/img/generate` 的 Markdown `prompt`。公开版本只保留通用执行规则；不要要求生图模型返回 JSON，也不要把本文件原样放进 Prompt。

## 核心原则

发生冲突时按以下顺序取舍：

```text
商品真实与用户明确要求
> 平台硬性规则
> 当前图片用途
> 用户品牌与风格偏好
> 品类与目标市场的一般经验
```

先把输入分为三类：

- **可见事实**：商品类型、主色、外形、材质、包装、可辨认文字和已有配件。
- **用户确认**：核心卖点、品牌要求、目标人群、精确文案和禁止事项。
- **不可推断**：功效、性能数值、认证、价格、折扣、赠品、未展示配件和品牌承诺。

只使用前两类信息，不把第三类写入方案或 Prompt。

- 看不清的颜色、材质和文字不要猜测；保持商品固有颜色，不虚构 Hex 色值。
- 平台和市场可以影响构图、信息密度、光线、氛围和缺省产物语言，但不能覆盖商品事实或用户明确要求。

## 商品一致性锁

套图策划时先根据可见事实和用户确认信息建立一份锁定清单。未知项写“未知，不补全”，不要猜测；整套图片逐字复用同一份清单。

```markdown
## 商品一致性锁

- 商品数量：{固定数量，默认 1 件}
- 主色与配色：{可见事实}
- 外形与比例：{可见事实}
- 材质与表面：{可见事实}
- 按钮、接口与结构：{可见事实}
- Logo、包装与文字位置：{可见事实}
- 已确认配件：{列表或无}
- 禁止变化：数量、颜色、轮廓、结构、Logo、包装、文字位置和配件数量
```

参考图有多张时，商品正面、侧面、背面和细节原图按事实优先级排在前面。生成图只能作为最后一张风格参考；Prompt 必须说明“最后一张只参考光影与氛围，不借用其中的商品、Logo、包装、文字或配件”。

### 参考素材支持角度

规划前按真实素材记录可用视图，例如“正面：main-001；佩戴：main-004；侧面：无”。没有对应参考证据时，不规划侧面、背面、内部、开口、接口、耳堵、包装背面或未展示配件；改用已有证据支持的正面、局部细节、组合陈列或佩戴效果。用户明确要求生成无参考角度时，先说明模型会推断结构并获得确认，不能把推断结果标记为商品事实。

## 套图规划

按用户数量选择不同用途，不固定七张，也不重复构图凑数量：

- **白底主图**：商品完整、轮廓清晰、无遮挡、无多余装饰。
- **核心卖点图**：一张只表达一个用户确认的购买理由。
- **使用场景图**：真实环境、合理尺度，商品仍是视觉中心。
- **功能说明图**：操作关系明确，不虚构功能或内部结构。
- **细节材质图**：合理近景、真实纹理、保持商品颜色。
- **尺寸规格图**：留出标注空间，数值必须由用户提供。
- **包装信任图**：只展示参考图或用户确认存在的包装与配件。

数量较少时优先主图、核心卖点和使用场景，再按需要加入功能、细节、规格与信任图。

## 渠道与市场

只向 Prompt 写入与本张图有关的要求。平台未指定时使用“通用电商”，不默认某个国家或平台风格。

- **Amazon**：主图遵循纯白背景、完整商品、无道具和促销文字等常见要求；副图强调真实场景与可信信息。
- **内容电商**（TikTok Shop、抖音）：移动端和首屏吸引力优先，画面直接，卖点短而清晰。
- **综合电商**（淘宝、天猫、京东、拼多多）：商品突出、信息层级清楚；可有营销氛围，但不能编造促销信息。
- **跨境平台**（Temu、Shopee、Lazada、AliExpress、OZON）：移动端易读、商品中心化、减少文化依赖；有可见文案时使用按下方规则解析的产物语言。
- **B2B 平台**（Alibaba）：突出规格、应用与可信度，只使用用户确认的工艺和资质。
- **品牌站**（Shopify）：优先品牌一致性、编辑式摄影和生活方式表达。

目标市场只作为视觉软偏好：结合当地文化习惯、信息密度和生活场景自然调整，避免刻板印象。用户要求平台合规时，提醒其上架前按平台当前政策复核。

### 产物语言默认规则

仅在成图包含标题、卖点或行动文案时解析产物语言；没有可见文字时不询问。按以下优先级使用第一个可确定的值：

1. 用户明确指定的产物语言。
2. 用户明确指定的站点或目标市场语言。
3. 平台默认语言。
4. 仍无法可靠判断时询问用户。

Agent 的对话语言不参与选择。用户提供的精确文案逐字保留；若精确文案与解析后的语言冲突，先询问是否需要翻译，不得静默翻译或改写。

| 平台 | 未指定语言时的默认值 |
| --- | --- |
| 淘宝、天猫、京东、拼多多、抖音 | 简体中文 |
| OZON | 俄语 |
| Amazon | 英语；已明确站点或目标国家时，使用对应市场语言 |
| Alibaba.com | 英语 |
| Temu、Shopee、Lazada、AliExpress、TikTok Shop | 优先目标市场语言；目标市场不明时询问 |
| Shopify | 优先已有品牌或店铺语言；无法判断时询问 |
| 通用电商 | 有可见文案时询问 |

### 渠道与用途推荐比例

以下是 Skill 的生成默认值，不是平台永久有效的强制政策。接口支持 `1:1`、`3:4`、`4:3`、`9:16`、`16:9`、`2:3`、`3:2` 和带参考图的 `original`。

| 渠道与用途 | 默认比例 | 可选比例 |
| --- | --- | --- |
| Amazon 主图与副图 | `1:1` | 场景副图可用 `4:3` |
| Temu、Shopee、Lazada、AliExpress、OZON 商品图 | `1:1` | 移动端纵图可用 `3:4` |
| 淘宝、天猫、京东、拼多多商品主图 | `1:1` | 纵向卖点图可用 `3:4` |
| TikTok Shop、抖音商品卡 | `1:1` | 内容流和竖版封面使用 `9:16` |
| Alibaba B2B 商品图 | `1:1` | 应用场景可用 `4:3` 或 `3:2` |
| Shopify 商品列表 | `1:1` 或 `3:4` | 横幅可用 `16:9` 或 `3:2` |
| 通用电商 | `1:1` | 纵图 `3:4`，横图 `4:3` |

- 用户明确选择接口支持的比例时，以用户要求为准。
- 用户要求接口不支持的比例时，不静默替换；说明最接近的支持比例，或告知需要额外裁切工具。
- 同一图片需要多个比例时，每个比例是独立计费操作，必须在执行前列入总操作数。
- 平台政策可能变化；用户要求严格合规时，提示按当前平台规则复核比例、像素和安全区。

## 品类视觉参考

品类只提供默认方向，用户风格和商品事实优先：

- 科技数码：均匀柔光、干净留白、中性色调、结构清晰。
- 游戏设备：冷色侧光、适度暗背景、力量感；不能牺牲商品细节。
- 家居用品：自然暖光、柔和通透、真实居住氛围。
- 运动装备：自然光、明快清晰、动作感和阳光活力。
- 服饰配件：柔和侧光、真实面料纹理、优雅克制。
- 美妆护肤：均匀柔光、干净透亮、精致材质；不虚构功效。
- 食品饮料：自然食欲感、真实色泽、干净卫生；不虚构配料和营养信息。
- 工具家电：功能关系明确、结构可信、使用环境合理。

默认真实商业摄影。只有用户明确要求插画、3D、动漫或其他形式时才改变媒介风格。

## 风格交互

用户没有明确风格偏好或说“你来定”时，Agent 自动选择方向，不增加选择步骤。

用户明确想看不同方向时，展示 3–4 套简短 Markdown 方案。方案应有明显差异；全局风格不写具体场景和道具。

```markdown
### 方案：{通俗风格名}

- 适合：{适用图片用途}
- 光影：{可跨图片复用的光线}
- 色彩：{商品原色与背景、强调色关系}
- 氛围：{可跨图片复用的商业氛围}
- 推荐原因：{不超过一句话}
```

## 生图 Prompt 模板

为每张图单独填写。将完成后的整段 Markdown 作为 `prompt` 字符串传给 `image transform`，参考商品图通过 `image`、`reference_images` 或 `reference_image_urls` 单独传递；多图同时传等长的 `reference_roles` 固定职责。

```markdown
# 电商图片任务

- 用途：{本张图片用途}
- 平台与市场：{目标平台和市场；未指定则写通用电商}
- 产物语言：{按产物语言优先级解析后的语言；没有可见文字则写“无文字要求”}
- 比例：{画面比例}

## 商品事实与卖点

- 商品：{参考图中确认的商品事实}
- 本张卖点：{一个用户确认的卖点；没有则不写}

## 必须保持

- 保持参考图商品的造型、比例、固有颜色、材质、包装结构、品牌标识和可见文字
- 不增加未经确认的配件、功能或商品结构；看不清的文字不要重造

{逐字放入本套商品一致性锁}

## 渠道要求

{仅写当前平台和市场对本张图片有用的要求}

## 套图统一视觉基线

- 光线：{全套共用光线}
- 色彩：{保持商品原色的统一色彩关系}
- 氛围：{全套共用商业氛围}

## 本张画面

- 参考证据：{列出支持本张构图和角度的参考图；没有证据的角度不得生成}
- 场景与构图：{场景、商品位置、占比和必要道具}
- 唯一表达重点：{本张图片的单一任务}
- 画面文案：{用户提供的精确文案逐字保留；否则只用目标语言表达用户确认的卖点；没有文字需求则删除}

## 禁止事项

- 不改变商品颜色，不遮挡关键结构，不生成重复商品或错误配件
- 不生成参考素材未展示的侧面、背面、内部、接口、扣件、耳堵或包装结构
- 不虚构功能、规格、认证、价格、促销、赠品和品牌信息
- 有精确画面文案时，不增加角度标签、说明文字、徽章、水印或其他可见文字
- 不使用浓重滤镜，不让场景和装饰抢过商品主体
```

删掉不适用的章节和所有占位符。白底主图只保留商品事实、保持要求、平台主图规则与纯白背景要求。

## 执行检查

- 每张使用新的 `request_id`，始终把原商品图作为参考。
- 同一套图逐字复用“统一视觉基线”，只改变本张画面。
- 已有用户认可的主视觉时，可追加为风格参考，不能替代原商品图。
- 白底主图默认使用 `image transform` 并明确纯白背景、商品居中和一致性要求。只有用户明确要求抠图、去背景、移除背景或抠出主体时，才使用抠图接口；“白底图”本身不是抠图意图。
- 精确文字、商品一致性和平台合规不作绝对承诺；本地化优先使用图片翻译。
- 执行前列出每张用途、比例、语言、点数和总操作数并获得确认。
- 交付时优先展示结果图、用途、`local_path` 和点数；request ID 与远程 URL 保留用于按需查看和问题排查，不默认堆给用户。

## 生成结果一致性检查

有能力查看结果图时，在交付前逐张对照商品一致性锁；无法查看时不要声称已经通过视觉验收。

- 商品数量、主色、轮廓和整体比例是否一致。
- 材质、按钮、接口、开口和关键结构是否变化或畸变。
- Logo、包装、可见文字的位置和内容是否明显错误。
- 是否新增、删除或替换了配件，是否生成重复商品。
- 商品与人物、家具和环境的尺度是否合理。
- 是否符合本张用途、选定比例和统一视觉基线。
- 是否出现未经确认的规格、功效、认证、价格、促销或赠品。

检查状态只使用“AI 初检通过”“需修正”“等待商家确认”。即使 AI 初检通过，也不能宣称已经符合平台最新政策或可以直接上架；商品细节、文字与合规性仍由商家最终确认。

发现明显漂移时，将该图片标记为“需修正”，说明具体问题并保留已经生成的结果。生成成功可能已经扣点，不自动再次付费生成；先告知用户重试成本并获得确认，再使用新的 `request_id` 修正。
