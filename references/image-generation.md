# 图片生成接口

## 接口与输入

- 接口：`POST /api/v1/img/generate`，同步返回。
- 每次固定生成 1 张，不传 `quantity`、`number`、`count` 或 `n`。
- `prompt` 必填。
- 参考图可传 0–6 张本地图片、data URL 或公网 HTTPS URL。CLI 接受 `reference_images`、`image` 数组或 `reference_image_urls`；本地素材直传 OSS，并以有序的 `reference_image_keys` 调用业务 API。
- 文生图默认比例 `1:1`；`original` 只能用于至少有一张参考图的图生图。
- 支持比例：`1:1`、`3:4`、`4:3`、`9:16`、`16:9`、`2:3`、`3:2`、`original`。
- 普通请求超时至少 120 秒；2K/4K 建议至少 180 秒。

## 模型选择与点数

| `model_alias` | 适用场景 | 点数/张 |
| --- | --- | ---: |
| `tpro-1k` | 主力创意与设计模型；适合海报、封面、信息图、营销活动主图、社媒素材、电商主图、商品场景图、复杂创意与含文字层级的复杂构图，也用于参考生图、纯改图、局部修改和未指定规格的普通增强 | 10 |
| `tpro-2k` | 更高分辨率的设计与复杂创意 | 12 |
| `pro-1k` | 用户明确指定时使用的人物/商品保持、改图、换场景、参考图生成 | 12 |
| `pro-2k` | 用户明确要求 2K 时的生成式高清重绘 | 12 |
| `pro-4k` | 用户明确要求 4K 时的生成式高清重绘，耗时最长 | 18 |

没有明确模型要求时，设计、生图、参考生图、纯改图和普通增强统一使用 `tpro-1k`。它优先服务于需要视觉创意、主体组织和信息层级的设计图，而不是像素级复刻。用户明确要求 2K/4K 高清增强时，自动使用对应的 `pro-2k`/`pro-4k`；用户显式指定模型时以用户指定为准。2K/4K 是生成式处理，不保证像素级或文字无损保持；包含活动标题、价格或品牌文案的成图也应校对可读文字。

## 提示词组装规则

- 从用户已提供的信息中组织“主体、场景、用途、构图、风格、光线、画面文字”，缺失的非关键项使用合理默认值，不连续追问。
- 参考图改图时优先写清“保留项”和“修改项”；不要只使用“优化一下”“更高级”等无法约束主体一致性的描述。
- 电商活动主图必须先锁定商品一致性：参考图商品是唯一核心主体，不改变商品品类、容器形状、包装结构、标签布局、主色和可辨认文字；只调整背景、光影、活动氛围和主图排版。
- 多参考图按编号建立职责：第 1 张锁定主体与比例，后续图片只补充明确角度、结构、材质、文字或风格。Prompt 中使用 `reference_roles` 明确每张图的用途，避免模型把多个商品拼成一个新主体。
- 图片内需要出现指定文案时逐字保留，用明确引号标识；不要自行添加价格、折扣、功效、认证或品牌承诺。
- 扩图只生成原画布外需要补充的内容，并强调保持主体、可见文字、色彩、光线和原构图关系。
- 高清增强强调保持主体身份、产品细节、可见文字和构图，不添加或删除内容；仍需向用户说明结果属于生成式重绘。

## 幂等、扣费与结果

- 同一应用、同一 `request_id`、同一参数重试会返回同一结果的新签名 URL，不重复生成或扣费。
- 同一 `request_id` 改变 `prompt`、模型、参考图或比例会被拒绝。
- 正在执行返回 `2042`；等待后复用同一 ID。已经失败的任务需要换新 ID 才会重新生成。
- 多任务必须为每张图使用独立 `request_id`；重做某一张时只复用该张的参考图顺序和 Prompt 基线，并生成新的 `request_id`，不要重新提交整套任务。
- 仅生成并保存成功后扣费；参数、余额、下载、安全审核和保存失败不消费点数。
- `result.url` 是可能过期的签名 URL。需要长期使用时及时下载保存；重新取签名必须以原 ID 和完全相同参数重放。
- 以响应体 `code` 判断业务结果；网关限流可能同时返回 HTTP 429。
