# 图片生成接口

## 接口与输入

- 接口：`POST /api/v1/img/generate`，同步返回。
- 每次固定生成 1 张，不传 `quantity`、`number`、`count` 或 `n`。
- `prompt` 必填。
- `reference_image_urls` 可传 0–6 张；只能使用公网 HTTPS URL，不支持 base64、本地路径、OSS key、内网地址或不安全跳转。
- 文生图默认比例 `1:1`；`original` 只能用于至少有一张参考图的图生图。
- 支持比例：`1:1`、`3:4`、`4:3`、`9:16`、`16:9`、`2:3`、`3:2`、`original`。
- 普通请求超时至少 120 秒；2K/4K 建议至少 180 秒。

## 模型选择与点数

| `model_alias` | 适用场景 | 点数/张 |
| --- | --- | ---: |
| `tpro-1k` | 海报、封面、信息图、复杂创意 | 10 |
| `tpro-2k` | 更高分辨率的设计与复杂创意 | 12 |
| `pro-1k` | 人物/商品保持、改图、换场景、参考图生成 | 12 |
| `pro-2k` | 2K 人物/商品/场景生成式高清重绘 | 12 |
| `pro-4k` | 4K 生成式高清重绘，耗时最长 | 18 |

原接口未传模型时默认 `pro-1k`；本 Skill 会按任务意图显式选模型。2K/4K 是生成式处理，不保证像素级或文字无损保持。

## 提示词组装规则

- 从用户已提供的信息中组织“主体、场景、用途、构图、风格、光线、画面文字”，缺失的非关键项使用合理默认值，不连续追问。
- 参考图改图时优先写清“保留项”和“修改项”；不要只使用“优化一下”“更高级”等无法约束主体一致性的描述。
- 图片内需要出现指定文案时逐字保留，用明确引号标识；不要自行添加价格、折扣、功效、认证或品牌承诺。
- 扩图只生成原画布外需要补充的内容，并强调保持主体、可见文字、色彩、光线和原构图关系。
- 高清增强强调保持主体身份、产品细节、可见文字和构图，不添加或删除内容；仍需向用户说明结果属于生成式重绘。

## 幂等、扣费与结果

- 同一应用、同一 `request_id`、同一参数重试会返回同一结果的新签名 URL，不重复生成或扣费。
- 同一 `request_id` 改变 `prompt`、模型、参考图或比例会被拒绝。
- 正在执行返回 `2042`；等待后复用同一 ID。已经失败的任务需要换新 ID 才会重新生成。
- 仅生成并保存成功后扣费；参数、余额、下载、安全审核和保存失败不消费点数。
- `result.url` 是可能过期的签名 URL。需要长期使用时及时下载保存；重新取签名必须以原 ID 和完全相同参数重放。
- 以响应体 `code` 判断业务结果；网关限流可能同时返回 HTTP 429。
