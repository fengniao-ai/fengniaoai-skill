# 蜂鸟AI 电商商品套图

编排原子能力，不复制其 HTTP 实现。进入套图策划后读取 `../../references/ecommerce-visual-guidelines.md`，只提取当前平台、市场、品类和图片用途需要的规则。

## 对话顺序

1. 首先获取商品素材。用户提供 1688、淘宝/天猫或 Amazon 商品链接时，先用 `fengniao-product-insight` 采集并下载资料，展示标题、属性和图片清单；用户直接提供本地商品图片或公网 HTTPS 图片时直接采用。后续场景图和卖点图使用参考图生图；看不清的颜色、文字、材质和配件不要猜测。
   用户明确要求分析时，说明主图数量和每张 0.5 点后分析全部去重主图；用户只要求制作套图时，推荐全主图分析并给出预计点数，让用户选择“分析后规划”或“直接用现有素材规划”，不能静默增加识图扣点。超过 10 张时让用户确认全部或选择范围。SKU 图只在变体差异影响套图时追加，详情图只在需要核对卖点、包装或版式时追加。采集信息与多图识别结果冲突时让用户确认。
   用户选择“分析后规划”时，必须读取完整 `product.json` 并结合逐图结果生成 `analysis/product-analysis.md`。进入卖点建议和套图规划前完整读取该文档；存在会影响商品身份、SKU、销售单位、尺寸、重量、材质、品牌或可见文案的关键冲突时先让用户确认。未生成综合分析或关键冲突未确认时，不建立最终商品一致性锁，不启动付费套图生成。用户选择“直接用现有素材规划”时明确标注未做综合识图分析，并只使用页面采集信息和可见参考图，不把不确定字段当作事实。
2. 下一轮只给出核心卖点建议，并询问用户采用、修改还是提供自己的卖点；可同时询问是否有明确风格偏好，不混入平台配置。
3. 用户确认卖点后，再补齐平台、目标市场、产物语言、比例和图片数量。用户已主动提供的信息直接采用；缺少地域信息时使用“通用电商”，不默认套用美国市场审美。
   只有成图包含可见文字时才确定产物语言，并按“用户明确指定 > 明确站点或目标市场 > 平台默认 > 询问用户”解析。Amazon 未指定站点时默认英语，淘宝、天猫、京东、拼多多和抖音默认简体中文，OZON 默认俄语；多市场平台没有目标市场时询问。平台默认不能覆盖用户要求，Agent 的中文过程说明不能写进成图。
   用户提供的精确文案必须逐字保留；文案与目标语言冲突时先询问是否翻译，不能静默翻译或改写。
4. 根据数量规划不同图片用途。默认不展示风格选择，由 Agent 自动定调；只有用户明确想看不同风格时，才展示 3–4 套简短 Markdown 风格卡片。
   规划前先列出素材实际支持的角度。只有真实参考图清楚展示正面、侧面、背面、开口、接口或包装结构时，才能规划对应视图；缺少侧面或背面证据时，自动改成已有素材支持的正面、细节或佩戴图，不能让模型补造结构。
5. 用表格列出每张图的用途、比例、语言和计费操作，不输出内部 JSON。
6. 使用 `node ../../scripts/fengniaoai.mjs account balance --input-json '{}'` 查询剩余点数。
7. 这是多操作工作流，执行前必须确认图片数量和计费操作。

如果用户一次性给齐素材、卖点和上架配置，直接整理并确认，不强迫用户重复多轮问答。用户说“你来定”“好看就行”时自动选择风格，不增加一次选择。

## Prompt 组装

1. 按图片用途为每张图分别组装 Markdown Prompt，不要求风格策划或生图接口返回 JSON。
2. 先从 `product-analysis.md` 的“用户确认后可用于规划的商品事实”建立商品一致性锁；每张 Prompt 都逐字复用这份锁和完全相同的“套图统一视觉基线”。不能把完整 `product.json`、字段异常、来源冲突或待确认信息直接写进 Prompt。
3. 每张只加入目标平台和目标市场对应的规则，不把完整平台、市场知识表塞进 Prompt。
4. 按参考表选择渠道与用途的推荐比例；不支持的比例不能静默替换，多比例版本分别计费。
5. 具体场景、构图、商品占比和唯一卖点随图片用途变化；字体和图标规则只用于确实需要文字的信息图。
6. 将完成后的 Markdown 直接作为 `image transform` 的 `prompt`，参考商品图通过 `image` 或 `reference_image_urls` 单独传递。
7. 未使用的模板章节直接删除，不把占位符传给接口，也不向用户展示内部 Prompt。

## 执行顺序

1. 白底主图使用 `fengniao-image-generate` 的 `image transform`；只有用户明确说“抠图”“去背景”“移除背景”或“抠出主体”时，才使用 `fengniao-image-tools` 的抠图输出。
2. 使用 `fengniao-image-generate` 的 `image transform` 逐张生成白底主图、场景图和卖点图；每张使用新的 `request_id`。
3. 多平台比例使用生图扩图能力，不调用旧扩图接口。
4. 仅在用户要求本地化版本时使用 `fengniao-image-translate`。
5. 每张都使用同一组有序商品参考图；第 1 张作为主商品基准，侧面、背面、包装和细节图只有在真实存在时才按固定顺序追加。已有经用户认可的主视觉时，可追加为风格参考，不能替代原商品图。
6. 生成后按商品一致性锁逐张检查；明显漂移时标记问题，不自动付费重试，先获得用户确认。检查结论使用“AI 初检通过”“需修正”“等待商家确认”，不能把生成式检查称为已经合规或可直接上架。
7. 完成后先给出总数、成功数、失败数、消耗点数和结果目录，再逐张展示图片、用途、比例、语言和检查状态；不能只展示一张代表图后让用户自行翻目录。远程 URL 与 request ID 仅在用户要求或排查问题时展示。批量文件直接保存为 `<batch_dir>/<id>.<实际格式>`；用户要求重做某张时，传对应 `task_ids` 先报价并确认，结果保存为 `<id>-v2`、`<id>-v3`，不得覆盖旧图。任务 ID 使用用途型名称且不能重复。
8. 共享商品参考图的套图从 2 张起优先使用 `fengniao-image-generate` 的持久化批量 action；11 张以上必须使用。新对话先用 `batch-list` 找回最近批次。批量执行器使用最多 10 个工作槽的滑动队列：任一任务结束后按原顺序立即补入下一张，始终不超过 10 个在途请求。服务端 20 QPS 是每秒提交上限，不是在途任务上限；多个 Agent 共用同一账号时仍以服务端合计限流为准。遇到 `429/30001` 时保留原 `request_id` 并按 `../../references/actions.md` 退避；连续限流时暂停队列，不无限循环。任务清单持续记录用途、Prompt、参考图顺序、比例和 request ID，重做时只提交指定图片。

不承诺生成图片能精确保留商品文字或让跨图商品像素级一致；需要文字准确性时使用确定性的 OCR/翻译工具。成功时优先展示自动下载的 `local_path`。
