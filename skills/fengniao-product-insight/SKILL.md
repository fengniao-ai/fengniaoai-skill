# 蜂鸟AI 商品资料与识图

使用共享 CLI `../../scripts/fengniaoai.mjs`。处理业务链路、计费、目录与事实冲突时读取 `../../references/product-workflow.md`。

## 商品采集

1. 获取 1688、淘宝/天猫或 Amazon 完整 HTTPS 商品详情页链接；由 CLI 自动识别平台，只有无法识别时才询问。
2. 执行 `product scrape`，默认保存 `product.json`，并将主图、SKU 图和详情图分别下载到商品子目录。
3. 从返回的 `artifacts` 中找到 `role=product-metadata` 的 `local_path`；若缺失则使用 `<product_dir>/product.json`。解析完整 JSON 后再展示标题、价格、全部属性、图片数量和本地目录，不能只依赖接口响应摘要或图片识别。价格、描述和属性只称为“来源页面采集信息”，不当作已验证事实。
4. 只要求采集时，完成后询问下一步：分析商品、制作电商套图、翻译现有商品图，或只保留资料。用户已明确要求“采集并分析”或“分析商品”时，告知主图数量和预计识图点数后直接分析全部去重主图，不再让用户逐张选择。用户只要求制作套图但未要求识图时，先推荐全主图分析并给出预计点数，让用户选择“分析后规划”或“直接用现有素材规划”，不能静默增加付费操作。

```bash
node ../../scripts/fengniaoai.mjs product scrape --input-json '{"url":"https://detail.1688.com/offer/801858383762.html"}'
```

## 识图分析

1. 使用本地图片或已经上传的临时素材；公网图片先下载到本地，不能把 URL 直接提交识图接口。
2. 一次调用分析一张图片。用户明确要求分析整个商品，或在迁移渠道、制作套图流程中选择“分析后规划”时，默认分析下载目录中全部去重主图；先按文件内容去除完全重复项，告知“共 N 张，预计 N x 0.5 点”，最多保持 3 个请求在途。主图超过 10 张时先展示清单，请用户确认全部分析或选择范围。用户明确说“第一张”“这张”或指定文件时，只分析指定图片。
3. 商品主图关注主体、外观、真实角度、结构、背景和可见文字；SKU 图只在变体差异影响任务时追加，详情图只在需要核对卖点、包装信息或页面结构时追加，不默认全部分析。
4. 不传自定义 Prompt、分析类型或模型。接口自动选择分析重点。
5. 每张分析保存为独立 Markdown。分析 URL 商品时，必须先读取完整 `<product_dir>/product.json`，再结合全部已选图片的逐图分析，在同一 `analysis/` 目录生成唯一的 `product-analysis.md`；不能只汇总识图结果，也不能把不同图片的推测合并成事实。固定结构、来源标注和冲突处理见 `../../references/product-workflow.md`。

```bash
node ../../scripts/fengniaoai.mjs image analyze --input-json '{"image":"./1688-801858383762/images/main/801858383762-main-001.jpg","analysis_id":"801858383762-main-001"}'
```

## 后续编排

- 制作电商套图：把 `analysis/product-analysis.md` 作为商品事实交接单；关键冲突经用户确认后，再交给 `fengniao-ecommerce-kit` 建立商品一致性锁和逐张方案。
- 商品图本地化：已有图中文字需要改成目标语言时，交给 `fengniao-image-translate`，不能用生图代替确定性翻译。
- 场景图或营销图：使用下载的主图作为第 1 张主体参考，SKU、背面和细节图只补充对应事实。
- 白底图：使用 `image transform`；只有用户明确要求抠图或去背景时才调用抠图。

不把采集标题、详情描述或识图推测直接写成商品功效、认证、折扣和品牌承诺。采集与识图冲突时并列展示来源，让用户确认，不擅自选择其一。
